# Android 7.0（SM-G9209）WebView 升级路径调研：社区版本 & 自编译可行性

调研时间：2026-09-29　设备：Samsung SM-G9209（zerofltectc）/ Android 7.0 / API 24 / Magisk 31.0

---

## 〇、结论速览

| 路径 | 结论 | 关键依据 |
|---|---|---|
| **官方 WebView** | **119.0.6045.x 就是天花板**，已装 119.0.6045.53 | Chromium M120 起 `default_min_sdk_version = 26`（直接读源码 config.gni） |

## 一、为什么 119 是天花板（源码级证据）

直接读取 Chromium 各分支 `build/config/android/config.gni`：

| Chromium 分支 | `default_min_sdk_version` | 对应 Android |
|---|---|---|
| **119.0.6045.199** | **24** | **Android 7.0** ← 最后一版 |
| 120.0.6099.216 | 26 | Android 8.0 |
| 124.0.6367.219 | 26 | Android 8.0 |
| 130.0.6723.86 | 26 / 27 | Android 8.0/8.1 |
| main（≈M15x） | 29 | Android 10 |

这与 [Thorium-Android issue #69](https://github.com/Alex313031/Thorium-Android/issues/69) 中的说明一致：
> Google deprecated KitKat (4.4) from M83, Lollipop (5.0) from M96, Marshmallow (6.0) from M107 and **Nougat (7.0) from M120**

并且 `M119` 分支实际发布的补丁远不止 `.53`——已确认存在 `119.0.6045.134 / .193 / .199 / .214`（`chrome/VERSION` 实测）。**你当前装的 `.53` 并不是 M119 的最后一个补丁。**

## 二、设备侧硬约束：WebView provider 白名单机制（三重验证）

这是决定「社区版/自编译能不能用」的关键，做了三层独立验证。

### 2.1 设备白名单内容（解包 framework-res.apk）

设备上的白名单是 Samsung 定制的 `res/xml/config_webview_packages.xml`，**只有一条，且没有 `signature` 属性**：

```xml
<webviewproviders>
    <webviewprovider description="Google WebView"
                     packageName="com.google.android.webview"
                     availableByDefault="true"/>
</webviewproviders>
```

### 2.2 AOSP 源码逻辑（android-7.0.0_r1）

`services/core/java/com/android/server/webkit/WebViewUpdateServiceImpl.java`：

```java
Signature[] packageSignatures;
// If no signature is declared, instead check whether the package is included in the
// system.
if (provider.signatures == null || provider.signatures.length == 0) {
    return packageInfo.applicationInfo.isSystemApp();
}
```

### 2.3 设备自身编译产物的反汇编（最强证据）

反汇编设备上的 `/system/framework/services.jar` →
`Lcom/android/server/webkit/WebViewUpdateServiceImpl;`：

```
83987a: iget-object v4, v10, Landroid/webkit/WebViewProviderInfo;.signatures:[Ljava/lang/String;
83987e: if-eqz  v4, 0012        # signatures == null  → 跳去 isSystemApp 分支
839886: array-length v4, v4
839888: if-nez  v4, 0019        # length != 0 → 才走签名比对
83988c: iget-object v4, v11, Landroid/content/pm/PackageInfo;.applicationInfo
839890: invoke-virtual ApplicationInfo.isSystemApp:()Z
839898: return v4               # 直接返回「是不是系统应用」
83989a: ...                     # 比对 Base64 签名（本设备走不到这里）
```

**三星的实现与 AOSP 完全一致。** 另外用 binder 直接查询 `webviewupdate` 服务，返回的 `WebViewProviderInfo` 中 signatures 数组长度为 0，与上面结论互相印证。

### 2.4 由此得出的结论

> **对包名 `com.google.android.webview`，本设备的唯一要求是「系统应用」——签名完全不做校验。**

推论：

1. **自编译 / 第三方重签名的 WebView 可以直接部署**，只要：
   - 包名是 `com.google.android.webview`（Chromium 默认编译出的是 `com.android.webview`，需改 manifest 或用 apktool 改包名后重签）
   - APK 落在 `/system/...` 下（Magisk 模块 overlay 即可满足 `FLAG_SYSTEM`）
2. 想用**其它包名**的引擎（如自编译保持 `com.android.webview`），才需要改 `framework-res.apk` 里的白名单 XML（AXML 二进制，改动风险更高）。
3. `availableByDefault` / `isFallback` 机制也存在，但不是必须。
4. 注意：如果 `/data` 里存在官方更新（当前就是 119.0.6045.53，versionCode 604505301），必须**卸载该更新或让自编译版本号更高**，否则 PackageManager 仍会优先用版本号高的那个。

## 四、自编译可行性评估

### 4.1 目标 A：编译 M119 分支（推荐，现实可行）

- **收益**：
  - 拿到 M119 的**更晚安全补丁**（`.193` / `.199` / `.214`，你现在是 `.53`）
  - 去掉 Google 品牌/遥测（`is_chrome_branded=false`、`use_official_google_api_keys=false`）
  - 可自定义特性开关，产物完全可控
- **成本**：与官方版本同源，无兼容性风险；WebView 单目标（`system_webview_apk`）构建即可
- **安装**：用你自己的 key 签名即可（见第二节结论），Magisk 模块 overlay 到 `/system/app/WebViewGoogle/WebViewGoogle.apk`

### 4.2 目标 B：M120+ 降 minSdk 到 24（研究性项目，不建议）

需要改的地方（很浅）：

```gn
# build/config/android/config.gni
default_min_sdk_version = 24            # 原本 26/29
min_supported_sdk_version = 24          # 有个 GN assert 要求 default >= min_supported
```

但真正的工作量在于：**M120 把 pre-O（API 26）的兼容代码清理掉了**。降回 24 后，所有「不再判断版本号就直接调用 API 26+ 接口」的地方都会在 Android 7 上崩溃，需要逐个回补 `Build.VERSION.SDK_INT` 分支。WebView 的代码面比完整 Chrome 小，但仍是一个需要 Chromium 底层功力的移植项目——**公网上没有任何团队做成过这件事**（Cromite/Thorium 都选择了抬高最低版本而不是回移）。

### 4.3 本机环境评估（实测）

| 项目 | 实测 | 判断 |
|---|---|---|
| CPU | Ryzen 7 7735H，16 线程 | ✅ 够（Chromium 建议 8 核以上） |
| 内存 | 30 GB（可用 ~10 GB） | ✅ 够（官方建议 16 GB+） |
| 磁盘 | `/home` 空闲 **731 GB** | ✅ 够（完整 checkout + 构建约 100–150 GB） |
| 工具链 | ninja / gn / clang 已有，**缺 depot_tools** | ⚠️ 需补 |
| **网络** | `chromium.googlesource.com` ❌ `commondatastorage.googleapis.com` ❌ `chrome-infra-packages.appspot.com` ❌ 全部不可达；清华/中科大/南大/阿里镜像可达但**都不镜像 Chromium 源码** | ❌ **硬阻塞** |

> 也就是说：**这台机器要自编译 Chromium，必须先解决代理问题**（源码、CIPD 工具链、NDK 都走 Google 的服务器）。硬件和时间都不是问题，网络才是。

### 4.4 部署方式（验证过的思路）

参照 [hddq/magisk-cromite-webview](https://github.com/hddq/magisk-cromite-webview) 的做法，做一个 Magisk 模块：

```
module/
├── module.prop
└── system/app/WebViewGoogle/WebViewGoogle.apk   ← 自编译产物（重命名为官方包名 + 自己的签名）
```

配套动作：
1. `pm uninstall com.google.android.webview`（清掉 /data 里的官方 119 更新，避免版本号压制）
2. 重启（Magisk 在开机时 overlay，PackageManager 扫描后 `FLAG_SYSTEM` 成立）
3. 验证：`dumpsys package com.google.android.webview | grep versionName`

## 五、给这台机器的实际建议

1. **当前状态已是 Android 7 的实际上限**（WebView 119 + 228 个根证书），先用着。
2. **性价比最高的下一步**：把 WebView 从 `119.0.6045.53` 升到 **`119.0.6045.193`**（M119 分支较晚补丁）。获取途径：
   - APKMirror 等源在本机和手机上都不可达（实测 000）；
   - 可行做法是**自编译 M119 分支**（顺带解决 .53→.19x 的补丁落差）。
3. **想真正现代化，只能换 Android 版本**：社区确实有 S6 的 Android 13 ROM（[AICP 18.0 zeroflte](https://xdaforums.com/t/rom-unofficial-13-zeroflte-zerolte-zenlte-noblelte-aicp-android-ice-cold-project-18-0-for-samsung-galaxy-s6-s6-edge-s6-edge-note5.4796321/)、[/e/OS-T (LineageOS 20 based)](https://xdaforums.com/t/rom-unofficial-13-t-e-os-t-lineageos-20-0-based-for-samsung-galaxy-s6-sm-g920f-zerofltexx-and-galaxy-s6-edge-sm-g925f-zeroltexx.4653475/)），设备树在 [samsungexynos7420](https://github.com/samsungexynos7420) 组织。
   **但**：该组织只有 `zerofltexx`（SM-G920F）/`zerofltecan`/`zerolte` 等设备树，**没有 `zerofltectc`（SM-G9209 中国电信版）**。跨型号刷入会碰基带/bootloader 差异，风险高，需要自行移植设备树——这是另一个量级的项目。
4. **可立即做的验证实验**（可选）：把官方 119 重签名成自己的 key 塞进 `/system`，重启看系统是否接受。按第二、三节的证据链推断会成功，但如果你想 100% 钉死「自编译产物能装」，可以做一次（需备份原 APK + 两次重启，失败可完整回滚）。

## 六、调研方法与可复现命令

```bash
# 1) 设备白名单（解包 framework-res.apk）
adb pull /system/framework/framework-res.apk
aapt2 dump xmltree --file res/xml/config_webview_packages.xml framework-res.apk

# 2) 设备实际校验逻辑（反汇编 services.jar）
adb pull /system/framework/services.jar && unzip -o services.jar "classes*.dex"
dexdump -d classes.dex > svc.asm
grep -n -A30 "WebViewProviderInfo;.signatures" svc.asm

# 3) 运行时查询 provider（binder）
adb shell service call webviewupdate 2   # getAllWebViewPackages
adb shell service call webviewupdate 3   # getValidWebViewPackages

# 4) Chromium 各分支最低支持版本
curl -s https://raw.githubusercontent.com/chromium/chromium/119.0.6045.199/build/config/android/config.gni | grep min_sdk
curl -s https://raw.githubusercontent.com/chromium/chromium/119.0.6045.214/chrome/VERSION

# 5) F-Droid 索引（清华镜像）批量查 minSdkVersion
curl -sL https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo/index-v1.json -o fdroid-index.json
```

**可信度说明**：第一、二节的结论来自三条独立证据链（AOSP 源码 / 设备资源 XML / 设备字节码反汇编 + binder 运行时数据）；第三节各项目的版本与 Android 要求来自其官方仓库 README、Release 元数据、F-Droid 官方索引与 Chromium 源码，均为直接读取而非二手转述。
